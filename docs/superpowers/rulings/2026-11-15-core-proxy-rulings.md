# Subproject 1 (core proxy): controller rulings

Decisions taken during the subagent-driven implementation of
`docs/superpowers/plans/2026-11-14-core-proxy.md` (branch `feat/core-proxy`), in the order they
were made. Each line states what was decided, why, and what it costs if wrong. Parked findings
from the final review are listed at the end.

## Rulings

- Ruling R1: CI and all docs use `python3 -m flake8|mypy|pytest` — Debian packages ship modules without commands — if wrong, only CI command lines change. (The plan was corrected accordingly.)
- Ruling R2: smuggling test uses one Stuffer and asserts exactly one terminator at the end — matches the spec §4.7 intent — if wrong, a test assertion changes. (The plan was corrected accordingly.)
- Ruling R3: T13 moves the store behaviour tests into tests/support/store_contract.py, and test_memory_store.py becomes a wrapper — avoids duplicated tests — if wrong, test files are rearranged. (The plan was corrected accordingly.)
- Ruling R4: T27 DB integration tests skip when ASSPNG_TEST_DB_URL is unset. The run continues, and the controller asks the user at the end to create a test DB and runs them then — creating a DB/user in the user's MariaDB is outside the worktree — if wrong, DB code is less verified until then.
- Ruling R5: tests/load/run_load.sh exits with a clear message when smtp-source/smtp-sink are missing. The nightly CI job installs postfix in the container, and the local load run is deferred to the test server (do not install postfix on the user's desktop) — if wrong, performance numbers come later.
- Ruling R6: T35 systemd-analyze verify: warnings about the non-existent user or paths are acceptable, and the test is skipped with a reason if verify cannot run in this environment — if wrong, unit-file errors surface on the test server instead.
- Ruling R8: repo lacks .gitignore (untracked __pycache__/ etc.) — Task 7 implementer also adds .gitignore (__pycache__/, *.pyc, .pytest_cache/, .mypy_cache/, .hypothesis/, .coverage, htmlcov/) — if wrong, trivial to adjust.
- Ruling R9: CI runs the whole tree (python3 -m pytest) instead of tests/unit only, so tests/security runs in CI — done as an extra in Task 7 together with .gitignore (R8) — if wrong, CI is slower.
- Ruling R10 (Task 9): accept the loader additions — at least one [[listener]] required; user.d stem validated via parse_path("<stem>").key; backend port 1..65535 — all sensible validations — if wrong, loosen later.
- Ruling R11: Address.domain stays the original text (forwarded verbatim, logged as sent); consumers needing the normalized domain use normalize_domain(addr.domain) or addr.key — CARRY to Tasks 11, 24-26 dispatches — if wrong, add an Address.normalized_domain property later.
- Ruling R12: EventBus — handler exceptions logged and skipped while staying subscribed; reconnect only on Redis/OS/timeout errors; run(handler, on_subscribed=None) awaited after every successful subscribe for resync — supersedes the earlier "any error reconnect" ruling — if wrong, consumers miss resync hooks. CARRY to Task 28: DomainRefresher passes on_subscribed=refresh.
- Ruling R13: fallback failure while NORMAL -> TEMPFAIL ("fallback store failed"), recoverable by probe — fail-safe — if wrong, a transient memory error tempfails briefly.
- Ruling R14: new StateTypeError(StateError) for WRONGTYPE/type mismatch in both stores; controller propagates it without counting or transitions, logs at ERROR — a key-collision bug must not tempfail all mail — if wrong, type bugs surface only as errors in logs. Sent to implementer before review.
- Ruling R15: effective score = check result score if non-zero, else configured checks.<name>.*_score (as implemented). Core checks in sp1 return 0 scores so config decides and admins can disable via 0 — CARRY to Tasks 16/17 — if wrong, a dynamic check could override an admin 0.
- Ruling R16: reload() into a store created empty creates the front context lazily (STARTTLS becomes available without restart) — if wrong, admins must restart after first adding certs. Sent to implementer before review.
- Ruling R17: front context loaded once (construction or R16 lazy creation) and never mutated; sni_callback authoritative; reload may run off-loop (build + single-assignment swap) — supersedes the earlier reload-into-front ruling — if wrong, a client that skips the callback path would see the first-ever cert.
- Ruling R18: after any BackendError the backend is broken; close() aborts the transport without QUIT (normal close keeps QUIT with 5s timeout) — a hung MTA must not hold failing sessions 5s each — if wrong, the MTA sees abrupt disconnects after failures (harmless). Sent before review.
- Ruling R19: redact_auth keeps the token after AUTH only if it is PLAIN or LOGIN (case-insensitive ASCII); any other token is redacted too — removes the ambiguity — if wrong, logs lose unknown mechanism names. Sent to implementer before re-review.
- Ruling R20: str-level redaction = line-start R19 rule (to end of line) PLUS a mid-line rule: AUTH as a whole word (no ASCII alnum before/after), case-insensitive, then [ \t]+, optional PLAIN/LOGIN + [ \t]+, then payload token [^\s"\\]+ -> token replaced by <redacted> (mechanism kept). Applies to message, exc_text and stack_info. Token-only (not to end of line) so a client-controlled maillog value (e.g. helo="x AUTH y") cannot blank out the rest of a maillog line and quoting stays intact. App code must not phrase its own messages as "AUTH <word>" (use "authentication"). — Why: closes exception and mid-line leaks without letting clients suppress forensic fields. — Cost if wrong: one benign token over-redacted in rare messages.
- Ruling R21: RedactionFilter strips every record attribute not present on a standard LogRecord (after reading `auth`), because JournalHandler copies record.__dict__ into journal fields. — Why: extras could carry raw client data to the journal. — Cost if wrong: a later task wanting structured journal fields must allow-list them.
- Ruling R22 (Task 23): DebugLog writes go through its own SimpleQueue + one lazily started daemon writer thread (spec §8.5: disk I/O never blocks the event loop); on_full is invoked on the writer thread, once per full episode, so the server must wrap it with loop.call_soon_threadsafe; new close() joins the thread. Rotation-aware (reopen when inode changes; resume after the file shrinks below the cap). — Why: debug.log is a log file under §8.5. — Cost if wrong: an extra thread while debug is in use.
- Ruling R23 (Task 23): rule times are wall-clock epoch (persisted across restarts); IP values normalised via parse_ip+network_key (/32, /64); FROM/RCPT/USER compared lower-cased, FROM value "<>" matches the null sender; match_envelope also matches ALL; once a tap is active it stays active for the session; DebugLog escapes control chars as \xNN and applies redact_text as a safety net; rules file written atomically with mode 0600; corrupt/unreadable file -> warning + empty rules, never a crash.
- Ruling R24: DebugRules persists synchronously on the loop (add/remove/clear/prune) — accepted: tiny JSON in tmpfs /run, only on rule changes/expiry; not hot path. Cost if wrong: microsecond stalls on rule changes.
- Ruling R25 (Task 24): Session.run() swallows every Exception (R_INTERNAL path) but re-raises asyncio.CancelledError after its finally-cleanup (slot release, backend close, maillog, tap) — "run never raises" means no error escapes; cancellation must stay cooperative for shutdown drain (Task 27). Cost if wrong: drain must catch CancelledError per session task (it should anyway).
- Ruling R26 (Task 24): Task 24 dispatches commands through a verb->handler mapping; STARTTLS/AUTH/MAIL/RCPT/DATA are not handled yet and take the unknown-verb path (R_NOT_IMPL, never forwarded) until Tasks 25-26 register handlers. Every client line reaches the tap/logs only via asspng.proxy.auth.redact_auth(line, in_exchange) (False in Task 24); over-long lines are never logged, only their length. Backend reply text is sanitised (control chars -> space) before relaying (Task 4 carry).
- Ruling R27 (Task 25/26): session.py is at 600 lines. Task 25 first extracts helpers that do not need Session internals (maillog record builder, _int/_seconds/_text config helpers) into asspng/proxy/session_util.py, and puts STARTTLS/AUTH/MAIL/RCPT handlers in asspng/proxy/session_envelope.py as functions taking the Session (documented package-private access), registered in the verb mapping; Task 26 puts DATA in asspng/proxy/session_data.py the same way. — Why: keep files focused without inventing a façade layer. — Cost if wrong: later refactor to a façade.
- Ruling R28 (Task 25, security): STARTTLS command injection (CVE-2011-0411 class). asyncio StreamWriter.start_tls keeps the StreamReader buffer, so plaintext pipelined after STARTTLS would be processed as if received over TLS. After writing R_TLS_READY and draining, with no await in between, discard any bytes already buffered in the reader (CPython internal reader._buffer, behind one documented helper), log a warning without content, count a protocol error, then start_tls. Mandatory test: "STARTTLS\r\nRSET\r\n" in one write -> RSET is never processed after the handshake. — Cost if wrong: relies on a CPython internal; the test pins it.
- Ruling R29 (Task 25): AUTH flow — AUTH after success or inside a transaction -> R_BAD_SEQUENCE; unsupported mechanism or bad base64 (AuthSyntaxError) -> R_BAD_ARG + protocol error, and if the backend exchange is open send "*" first and swallow its reply; user_blocked checked as soon as the username is known and before forwarding the line that carries it (cancel an open backend exchange with "*"), blocked -> R_AUTH_TEMPFAIL; continuation lines tapped/logged via redact_auth(line, in_exchange=True), in_exchange driven by the MTA's 334; 4xx from MTA not counted as failure; MAIL FROM AUTH= parameter dropped (never forwarded); MAIL/RCPT forwarded rebuilt from parsed data with allow-listed parameters only (SIZE, BODY, SMTPUTF8, RET, ENVID / NOTIFY, ORCPT); MAIL before HELO/EHLO or nested MAIL -> R_BAD_SEQUENCE; STARTTLS inside a transaction -> R_BAD_SEQUENCE; recipients-per-message limit -> R_TOO_MANY_RCPT (not a protocol error); TLS state read from writer.get_extra_info("ssl_object") at start (implicit TLS) and after STARTTLS; handshake failure -> close, result "disconnected", info log.
- Ruling R30 (Task 25): plan gap — spec §5.6 AUTH '421 + IP score' and brief 'the auth IP score' have no setting; Task 25 adds abuse.auth_failure_ip_score (count, default 10, same level/style as the other abuse.* keys) to asspng/config/settings.py. — Cost if wrong: one more key to rename later.
- Ruling R31 (Task 25 I1): (a) on_auth always ends (finally) by discarding bytes already buffered in the reader via _discard_buffered (count-only warning; RFC 4954 makes AUTH last in a pipeline group and PIPELINING is not offered); (b) a client line whose verb is not a known SMTP verb (not in the dispatch table nor the locally answered/never-forwarded set) is tapped/logged by length only, "<unknown command: N bytes>" — covers payloads arriving in a later segment. Known verbs stay tapped redacted. — Cost if wrong: typo'd verbs lose content in debug output.
- Ruling R32 (Task 25, spec ambiguity §4.5 vs §5.6): the "next AUTH -> 421 + auth IP score" escalation flag is armed only by the network-level AUTH-phase refusal (AuthLimitsCheck R_AUTH_TEMPFAIL), not by the per-username block nor by a fail-closed state error (those give 454 only). — Why: an attacker elsewhere locking a victim's account must not get the victim's network scored. — Cost if wrong: slightly weaker escalation for user-targeted guessing from one network (still capped by the network counter).
- Ruling R33 (Task 26): the brief's maillog result "closed" for a client disconnect is replaced by "disconnected", the value Task 24 established and pins; per-message results: accepted / accepted-test / rejected / tempfailed / disconnected / timeout. — Cost if wrong: rename one string.
- Ruling R34 (Task 26): DATA lives in asspng/proxy/session_data.py (R27 pattern). Task 6 carry: stop feeding DataReceiver once feed() returns True; a MessageBuffer/sink failure (disk full, OSError) switches to discard mode until end-of-data, then R_TEMPFAIL_CMD + RSET to backend + maillog tempfailed. Data block/total timeout -> R_IDLE, close, maillog timeout. Header fields built by ASSP-NG never contain CR/LF from check reasons (sanitise). With tap.headers the outgoing header lines are tapped as P>M (redacted); bodies never. health.record events: "accepted", "rejected", "tempfailed" (CARRY to Task 29 with session_error, backend_lost).
- Ruling R4 (update 2026-11-15): with a local MariaDB available, the controller generated a random test credential outside the repository (mode 0600) and asked the user to create the test database as DB root; the DB suite then ran against MariaDB 11.8 (all MySQL parameters passed). The password is never printed or committed.
- Ruling R35 (Task 26 I2): pipelined leftover after end-of-data does NOT reject the message: run checks and deliver as normal, relay the reply, then count one protocol error (no reply of its own), log only the byte count, discard the leftover; if that reaches limits.session.protocol_errors, add abuse.protocol_error_ip_score and send R_TOO_MANY_ERRORS after the message's reply, then close. Fix the module docstring ("dropped unread"). — Why: security equal (end-of-data unambiguous to both sides, leftover never reaches the MTA), reliability decides. — Cost if wrong: pipelining clients are only penalised, not refused.
- Ruling R36 (Task 26): header-block limit lowered from 1 MiB to 256 KiB (still 552 "Message header too large"): header copies live outside the buffer budget; 500 sessions x 1 MiB x ~2 copies could exceed MemoryMax 512M. — Cost if wrong: rare legit messages with >256 KiB headers refused (Postfix header_size_limit default is 100 KiB per field).
- Ruling R37 (Task 27): the repository/migration tests run against two backends via a parametrised URL fixture: SQLite (tmp file, always) and MySQL/MariaDB (only when ASSPNG_TEST_DB_URL is set, R4). The schema stays portable (SQLAlchemy JSON, server_default CURRENT_TIMESTAMP, mysql_charset/collate kwargs ignored by SQLite). — Why: real RED/GREEN for DB code now instead of untested until the user creates the test DB. — Cost if wrong: SQLite hides a MySQL-only bug; the MySQL run covers it later.
- Ruling R38 (Task 27): Alembic programmatic config passes the DB URL through config.attributes["url"] (env.py builds the engine from it), never set_main_option — ConfigParser interpolation breaks on '%' in URL-encoded passwords. Engines use pool_pre_ping=True, pool_recycle=3600 and, for pymysql, connect_args connect_timeout=5, read_timeout=10, write_timeout=10 so a dead DB never hangs the refresher thread. The URL/password is never logged (render_as_string(hide_password=True) if needed). Duplicate add raises DomainExistsError(ValueError) translated from IntegrityError. Domains stored via normalize_domain. Each change writes its audit_log row in the same transaction (actions "domain.add"/"domain.remove").
- Ruling R39 (Task 28): DomainRefresher.refresh() never raises (catches Exception, logs type only, no URL); runs source_load and save_snapshot/load_snapshot via asyncio.to_thread; overlapping refreshes are coalesced with an asyncio.Lock (a refresh requested while one runs waits and then runs once more at most); on_event ignores any message other than "domains-changed" and never raises; db-down duration measured with an injectable monotonic clock from the first consecutive failure and reset on success; on_db_down(seconds) is called on every failed refresh. The app (later task) wires bus.run(refresher.on_event, on_subscribed=refresher.refresh) per R12. run() calls refresh() immediately, then every interval_s, and stops only on cancellation.
- Ruling R40 (Task 29): HealthState counters hold every recorded event name (accepted, rejected, tempfailed, session_error, backend_lost) — §8.4 shows the first three; extra keys are harmless; "tempfailed" and "backend_lost" are never summed. snapshot() derives "redis" from mode (NORMAL -> "ok", else "down") and "backends" from backend_result state (listener -> "ok" / "down", down = last result failed). Alerter gains keyword args instance: str and sender: str | None (default f"assp-ng@{socket.getfqdn()}"); smtp_server is "host:port"; webhook accepts only http/https URLs; event names are sanitised to a header-safe token and message text never goes into headers; the per-event rate limit applies to attempts (a failed delivery still consumes the slot) and notify returns False on failure. HealthServer binds only the given host, reads at most 8 KiB of request with a 5 s timeout, answers HTTP/1.0 with Content-Type application/json and Connection: close, GET /health only (HEAD/other methods/paths -> 404 or 405), never raises into the loop.
- Ruling R41 (Task 30, security): ControlServer binds under umask 0o117 so the socket is never world-accessible, then chmod 0660 and chown(-1, gid of `group`) when the group exists (PermissionError on chown -> warning, keep 0660). Stale-socket handling: remove the path only if it is a socket (S_ISSOCK) and nothing answers a connect; a live listener or a non-socket path -> refuse to start (raise). close() unlinks only if the path still has the inode we created. Protocol: requests one JSON object per line, StreamReader limit 64 KiB (oversize -> error reply, close); idle timeout 30 s per connection; cmd must be str and args a dict (else error); handler ValueError/KeyError/TypeError -> {"ok": false, "error": str(exc)}; any other exception -> "internal error" plus a log with the type; non-serialisable result -> "internal error". Several requests per connection are processed sequentially. control_request applies timeout_s to the whole exchange, reads a reply line up to 1 MiB, raises RuntimeError(error) on ok=false and lets TimeoutError/OSError propagate.
- Ruling R42 (Task 31, shutdown): Session gains notify_shutdown() (sets a flag) and tracks whether it is idle-waiting for a client command. Application.shutdown closes listeners, waits up to timeouts.shutdown for sessions, then calls notify_shutdown() on the rest and cancels their tasks. In the cancellation cleanup (R25) a shutting-down session that was waiting for a command writes R_TEMPFAIL (best effort, bounded ~1 s) before closing — never mid-reply or mid-DATA, so the protocol is never corrupted — and its maillog result is "shutdown". Then stores are closed.
- Ruling R43 (Task 31): the connection handler guards Session construction and run(): any Exception building the Session (Task 24 minor: parse_ip, config reads, SessionTap, default_policy) closes the writer (abort on timeout), logs the type, records health "session_error"; session tasks are kept in a set (strong refs) and removed on completion.
- Ruling R44 (Task 31): SessionDeps are built per connection from the current snapshot, so a session keeps the config it started with for its whole life (slightly stronger than §7.5 "running transactions keep their settings"; new sessions get the new config).
- Ruling R45 (Task 31): Application.start raises ConfigError with all errors on invalid config; main() prints every error to stderr and returns 2 (never a traceback). main returns 0 after a graceful shutdown.
- Ruling R46 (Task 31, wiring carries): HealthServer(status_code=HealthState.status_code); Housekeeper.tick every ~10 s from a loop task; Alerter clock = time.time; DebugLog on_full -> loop.call_soon_threadsafe(rules.clear + warning); bus.run(refresher.on_event, on_subscribed=refresher.refresh) (R12); StateController(on_change=...) schedules Alerter.notify for entering/leaving DEGRADED and entering TEMPFAIL; backend_result reaching 3 consecutive failures schedules an alert (wrapper around HealthState; fire-and-forget tasks kept in a set); memory soft limit crossing -> alert once per crossing, and force_tempfail while DEGRADED; schema revision mismatch -> alert + do not load from DB (snapshot); certificate expiry checked daily, alert below 14 days; WATCHDOG=1 every 10 s from the loop; all background loops never die on an exception (log type, continue) and stop on cancellation.
- Ruling R47 (Task 32): CLI global option --config-dir PATH (default /etc/assp-ng); the explicit root check (euid 0) for set/unset/init applies only to the default system dir, so tests use tmp dirs; scope -> file: sys=assp-ng.toml, default=default.toml, domain:<d> -> domain.d/<normalize_domain(d)>.toml, user:<a> -> user.d/<lowercased address>.toml; scope values are strictly validated (no '/', '\\', NUL, '..', leading '.', control chars; domain must be a valid normalised name; address must parse) — path traversal is impossible; new files mode 0640, existing mode kept, .bak keeps the original's mode; atomic write = temp in same dir + fsync + os.replace; systemctl reload only via an injectable runner and only when `systemctl is-active --quiet assp-ng-proxy` succeeds (never in tests); audit via write_audit when db.url is configured — audit failure prints a warning, the validated change stays; config check probes are injectable, print OK/FAIL per item, exit 1 on any failure; docs/configuration.md is generated and a test asserts it equals render_reference(REGISTRY) (no drift). Task 8 carry: improve setting descriptions (duration suffixes, meaning of 0, which modes use ip/msg score, "network" = prefix grouping) and add a test pinning (key, default, level) for keys consumed by later tasks.
- Ruling R48 (Task 31 I1/I2): the loader validates database.url with sqlalchemy.engine.make_url and health.listen as host:port with a loopback host (reuse loader _is_loopback), raising ConfigError naming the key WITHOUT echoing the value — so both start (exit 2) and reload (keep config) catch them. start() logs only the exception type on failure; main() catches Exception -> "cannot start: <type>" on stderr, exit 1, no traceback.

- Ruling R50 (Task 33): all ops commands honour --config-dir (R47) and read config via load_config; the DB URL/password and webhook paths are never printed (R38/R48/R49); notify builds the Alerter with min_interval_s=0 and the wall clock; audit actor = "$SUDO_USER (cli)" falling back to getpass.getuser(); domain add/remove publish "domains-changed" on "<prefix>events" only after the DB commit — a publish failure prints a warning and still exits 0 (the refresher's periodic refresh catches up); pb commands require Redis (exit 1 with a clear message if down — MemoryStore state of a DEGRADED proxy is not reachable from the CLI); pb remove --forget also deletes the history key; pb block validates the duration locally; debug on parses kind:value / all and --for locally (bad syntax -> exit 2) while limits are enforced by the server (refusal -> exit 1 with the server's message); control socket missing/permission denied -> exit 1 with a hint (run as root or a member of assp-ng); exit codes: 0 ok, 1 operation errors, 2 usage/config errors; no traceback ever reaches the user.
- Ruling R51 (Task 32 fixes): new files and directories inherit the group of their parent directory (os.chown(path, -1, parent_gid) via fchown on the temp fd; failure -> warning, never a crash) with modes 0640 / 0750; an exclusive fcntl.flock on <config-dir>/.assp-ng.lock (created 0640) wraps validate+write for set/unset/init; the validation copy dereferences symlinks (copytree symlinks=False) so nothing outside the temp copy is written during validation.
- Ruling R52 (Task 34): master.cf is rewritten as text (plan-mandated) rather than via postconf -M# — needed for the "# disabled by assp-ng <date>" marker and an exact diff; guarded by `postfix check`, verify and automatic rollback. A service's continuation lines (leading whitespace) are commented out with it. Idempotent: a master.cf already containing "# added by assp-ng" internal services yields an empty plan with a note; a port held by our own added service is not a conflict. ports_in_use comes from `ss -Hltn` via the injected run (read-only). Subprocess calls use argument lists (never a shell) with timeouts (60 s) and checked return codes. Backup: copytree of /etc/postfix with metadata and symlinks preserved into backup_root/postfix-<UTC timestamp>/ (dirs 0700). - Ruling R56 (Task 34 fixes): (C1) parser follows readlline exactly — a logical line continues across blank, whitespace-only and '#' lines and ends only at a line starting with neither whitespace nor '#'; comment lines inside a disabled service are commented with it; plus a guard: before apply, run `postconf -c <tmpdir> -M -P` on the planned text (tmpdir holds a copy of main.cf + planned master.cf) and refuse unless the only differences from the current `postconf -M -P` are the disabled services and the two added ones. (Minors pulled in, data-safety) backup dir created exclusively, rmtree only a dir this call created; temp file and directory fsync before os.replace; _newest matches only ^postfix-\d{8}T\d{6,12}Z$ exactly as the code names them.
